# Worked runtime addition

The reviewed source already has a focused transition guard, but the staged project lacked a compact dependency-free regression lab covering all policy edges. The addition loads the production `assertValidRunTransition` and `VALID_RUN_TRANSITIONS` behavior through the real service module. It verifies both PENDING targets, both RUNNING targets, representative terminal refusals, direct PENDING-to-COMPLETED refusal, and error detail containing both states.

Before the lab, a status table could drift without a broad runtime signal. After it, a test names each lifecycle contract. The test does not recreate the transition map; it reads the exported guard and checks its error. See [runtime-allocation-state-lab.test.mjs](../tests/runtime-allocation-state-lab.test.mjs). A production comment syntax fix is included: the route glob contained a block-comment terminator. The [original error module](snapshots/errors.ts.original.txt) preserves the exact before bytes. The improvement is intentionally educational and bounded. A follow-up provider harness should call the actual worker with tenant-scoped repository doubles or a database, force computation failure, and verify that result rows and FAILED status obey the intended transaction boundaries. That makes the exercise useful for reviewing a state change without installing the full application stack.

# WW6 allocation-run state lab

This course studies allocation run transitions in [allocationRunService.ts](../src/services/allocationRunService.ts) and its explicit `assertValidRunTransition` policy. The service creates and queues runs, attempts a RUNNING transition, computes results, replaces allocation result rows, and records terminal outcomes. The reviewed path already has a clear PENDING/RUNNING/COMPLETED/FAILED state machine, so this staged improvement is a production-source policy lab with a real error-module comment syntax repair. [runtime-allocation-state-lab.test.mjs](../tests/runtime-allocation-state-lab.test.mjs) executes the actual service module's transition guard.

The lab covers PENDING to RUNNING or FAILED, RUNNING to COMPLETED or FAILED, terminal refusal, and skipping directly to COMPLETED. Run the command in VERIFICATION.md from the project directory. The chapters connect the pure transition contract to tenant-scoped repositories and queue processing, then give traces, graduated practice, separate solutions, and limits. The VM run does not open Prisma, execute aggregation, or prove worker failure recovery. Those boundaries are explicit so a junior engineer does not mistake a state table check for full queue correctness.
